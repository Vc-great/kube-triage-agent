# Issue #28 Gate B：面试讲述

## 60–90 秒口述

“Gate A 已经能按估算预算安全裁掉旧的完整轮次，但丢掉的历史完全不可见。我在它之上加了默认关闭的按需摘要：只有 Gate A 确认 `trimmed` 后才触发。摘要源必须是连续、已结束、Tool ID 配对正确的只读诊断轮次，源预算和 12 秒超时都有硬上限；摘要模型不绑定任何工具。它返回受限 JSON，通过字段、长度、轮次引用和危险内容检查后，才作为带‘历史参考、非实时证据’标签的普通 AI 消息放到临时送模视图里。随后我用 Gate A 原估算器重算总预算，不合格就回退原安全裁剪视图。原始 State 和 Checkpoint 完整保留，缓存只存摘要、覆盖轮次及原始消息 SHA-256 指纹；新轮次可复用，同轮失败不重复请求。离线 10/20 轮可摘要并命中缓存，30 轮因源预算超限安全回退；260 个测试通过。FakeModel 证明协议与边界，不能证明真实模型的事实保留、抗注入或净 Token 收益。”

## 递进追问

1. 为什么缓存要同时校验连续前缀长度和原始消息 SHA-256？回放或历史改写时怎样退化？
2. 摘要合法但最终模型输入仍超预算，或摘要请求 429/超时时，为什么只能回到 Gate A 的 `ContextPlan`？
3. 哪些离线不变量可以证明，哪些仍需真实模型加 Mock MCP、人工事实评分及真实 usage 数据？
