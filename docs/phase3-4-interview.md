# Phase 3-4：结果可复述版

## 约 90 秒

“这次做的是受控工程评测：真实 `gpt-6-luna`、正式 LangGraph/Aegra 0.10.8 和隔离 PostgreSQL，但 Kubernetes Reader 全部是冻结的合成 Mock。四组对照分别为只开 Gate A、Gate A 加摘要、Gate A 加 Memory、三者组合；同一个案例的旧对话结构与事实在四组一致。12 个新案例覆盖旧 UID、摘要与历史案例冲突、403/404、错 Pod 回执、Store 超时、紧预算和多工具证据，计划 144 次正式运行，重复次数不会被说成独立生产故障。

正式前先发现 `_has_tool_evidence()` 只要任意成功工具回执就会返回真，连请求目标 A 却返回 Pod B 的成功回执也算进去。真实模型在单独负例里没有误诊，但 Graph 自身兜底过宽；我保留了修复前轨迹，补了失败回归，再让明确目标的回答必须通过目标 `pods_get` 的身份和 HMAC 核验。403、404、错目标时由 Graph 给出未核验的安全回执。修复后的代码和旧 Pilot 数据没有混入同一个正式分母。

“过程中还发现首次正式批次四组 System Prompt 不同，所以在 102/144 次后整体作废、另建数据库和批次；有效的 `formal-v2` 统一提示词并完成 144/144。自动规则初筛 A/B 为 36/36，C/D 各 35/36：C 有一次 4 决策上限未完成，D 有一次未调用目标 Reader；都安全降级但没有完成诊断。B-A 没有质量增量，C-A 与 D-B 各少 1/36，D-C 总量持平但失败案例不同。四组 P34-09 共 12 次收到错误 Pod 的成功回执，均未把目标视为已核验。摘要组时延约翻倍，已知含摘要 Token 下界也更高；Memory 没有清晰诊断收益。独立的 32 次故障注入中，Store 超时和摘要超时没有造成历史冒充当前证据；有一次摘要组因上下文超预算安全返回未完成。匿名同源辅助 Judge 提出一处因果措辞争议，34 条盲审材料等待真人评价。”

结论只针对‘真实模型 + 合成 Reader’，不代表生产 Kubernetes 准确率。用户本人 Web 审批和人工盲审尚未完成，Memory 也不能因为展示了历史引用就被认定提升了诊断。”

## 面试追问

**为什么是四组对照？** B-A 看摘要增量，C-A 看 Memory 增量，D-B 看有摘要时 Memory 增量，D-C 看有 Memory 时摘要增量。四组模型、System Prompt、Reader Schema、当前合成证据、预算和历史事实相同；各自数据库与 Thread 隔离。

**为什么不能把 Aegra Run success 当诊断正确？** `success` 只说明 Graph 跑完。模型可能没有取得目标证据、达到 4 次决策上限、只给泛化未完成答复，或将历史误当现态；这些要按冻结 Gold、ToolMessage 配对和单独规则判定，失败保留在 ITT 分母。

**Store 超时如何模拟？** 在 `Store.asearch()` 边界注入受控 `TimeoutError`，Checkpointer 所用 PostgreSQL 保持正常；它不是声称真实数据库断网。摘要超时同样是代码注入，不冒充外部 Provider 故障。

**为什么不自动启用 Memory？** Phase 3-3 既有 A 60/60、B/C 各 59/60，Memory 组输入 Token 增加；本次必须看新的配对质量和安全回归。历史引用是后端展示，不是模型推理收益。真人盲审未完成时，结论保留证据等级与适用边界。
